# Landshop Native V5 — Internal Device Builds

This release setup **does not automatically publish** to Google Play or Apple App Store. It reuses the existing Landshop website, existing customer accounts, private KYC bucket and approved official logo.

## What is prepared

- Official Landshop logo-derived 1024×1024 app icon, Android adaptive icon and branded splash. They are generated by `scripts/prepare_brand_assets.py` from `apps/portal/public/media/logo.webp`; no alternative brand mark or stock artwork is introduced.
- The Expo SDK 58 `expo-splash-screen` configuration, Android package `com.landshopnigeria.customer` and iOS bundle ID `com.landshopnigeria.customer`.
- One manually triggered GitHub Actions workflow: [Landshop Native Internal Builds](https://github.com/landshopnigeria/landshop/actions/workflows/build-landshop-native-internal.yml).
- `android-internal` generates an APK; `ios-simulator` builds a simulator test application; `ios-internal` requests a provisioned iOS installation for registered devices.

## Owner/administrator configuration required once

1. In the Landshop-owned Expo/EAS account, create or link **one** project representing `landshop-customer`. Record its existing **EAS project UUID**; do not create a second Supabase project.
2. In GitHub repository **Settings → Secrets and variables → Actions**, set:
   - Secret `EXPO_TOKEN`: a limited-scope access token for that Expo project, stored as a GitHub Actions secret (not committed).
   - Variable `LANDSHOP_EAS_PROJECT_ID`: the existing EAS project UUID.
3. In the Expo/EAS project under the **Preview** environment, configure `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY` with the publishable key of the existing Landshop Supabase project. This is a client-facing key, never a service-role/secret key. The configured project URL is `https://iwkfagzkogzidrbbezds.supabase.co`.
4. Complete EAS signing credential setup. Android internal APK signing can use managed credentials. Real-device iOS internal builds require Apple Developer enrollment, registered devices, and provisioned credentials. This workflow cannot supply those credentials by itself.
5. Leave native OAuth callback flag **OFF** until device testing and exact Supabase redirect allowlisting are complete.

## Start an authorized internal build

Open the link above, select **Run workflow**, use branch `main`, choose exactly one internal profile, then run. The workflow validates the app identity, compiles the mobile code, creates official brand artwork, links the existing EAS project, checks its Preview configuration, and requests an internal build. Its logs contain the resulting EAS build reference.

A successful GitHub Action only proves that EAS accepted and completed the build. Engineers must still download the actual APK/IPA, install it, and test on real devices before public release.

## Acceptance checks before any public mobile release

- Android phone, Android tablet, iPhone, iPad and iOS Simulator launch, offline/reconnection, font scaling and screen reader accessibility.
- Email/password sign-in, two-step signup, email confirmation, password reset, Google login callback and referral invitation attribution with disposable accounts. The currently disabled native OAuth flag must not be enabled until verified.
- KYC camera permission accepted/denied, JPG/PNG/WebP/PDF selection and 10 MB limits, secure owner-only uploads, document review and protected account isolation. Use synthetic documents, not customer/staff identity files.
- Application history, drafts, missing timeline service, referral QR sharing and wallet read-only behavior.
- Privacy/legal approvals for identity data retention, account deletion, breach response and in-app disclosures.
- Obtain explicit Landshop owner approval before creating signed production binaries or submitting to either app store.

cd mobile/customer-app
npm install

npm run typecheck
npm test
